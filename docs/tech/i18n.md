# i18n — système de traduction custom

L'application est en français. Un système léger, sans dépendance externe, centralise tous les textes visibles afin
d'éviter le texte en dur dans les templates et de permettre une localisation ultérieure.

---

## 1. Fichiers

- `frontend/public/i18n/fr.json` — dictionnaire unique, chargé au démarrage (`APP_INITIALIZER` / `provideAppInitializer`)
- `frontend/src/app/core/i18n/translate.service.ts` — charge le JSON, expose `translate(key, params?)` et un signal `loaded`
- `frontend/src/app/core/i18n/translate.pipe.ts` — pipe pur `translate`, standalone

---

## 2. Structure des clés

Clés en `camelCase`, hiérarchie par écran puis par zone :

```json
{
  "common": { "save": "Enregistrer", "cancel": "Annuler", "clear": "Effacer", "ok": "OK", "nobody": "Nobody" },
  "board": {
    "title": "MR Board",
    "toolbar": { "refresh": "Rafraîchir", "settings": "Paramètres", "syncedJustNow": "Synchronisé à l'instant", "syncedAgo": "Synchronisé il y a {{minutes}} min", "syncing": "Synchronisation en cours…" },
    "banner": { "noToken": "Aucun jeton GitLab configuré.", "cacheHint": "Les données affichées sont celles du dernier cache.", "configure": "Configurer" },
    "filters": { "drafts": "Drafts", "mine": "Mes MRs", "add": "Ajouter un filtre", "project": "Projet", "author": "Auteur", "assigned": "Affecté à", "assignedHint": "Affecté à (Reviewer OU Affecté)", "approved": "Approved", "commented": "Commenté", "yes": "Oui", "no": "Non", "all": "tous", "search": "Rechercher…", "count": "{{mrs}} MR(s) · {{projects}} projet(s)" },
    "columns": { "project": "Projet", "author": "Auteur", "title": "Titre", "difficulty": "Difficulté", "comments": "Commentaires", "reviewer": "Reviewer", "assignee": "Affecté", "approved": "Approved", "readySince": "Depuis Ready", "opened": "Ouverte", "openedAt": "Date d'ouverture", "menu": "Colonnes" },
    "difficulty": { "easy": "Easy", "medium": "Medium", "hard": "Hard", "meta": "{{files}} f · {{lines}} l" },
    "ready": { "today": "aujourd'hui", "days": "{{days}} j", "openedAgo": "ouverte il y a {{days}} j", "openedToday": "ouverte aujourd'hui" },
    "empty": { "title": "Aucune MR ne correspond aux filtres.", "clear": "Effacer les filtres" },
    "errors": { "load": "Impossible de charger les MRs.", "sync": "La synchronisation a échoué." }
  },
  "settings": { "...": "..." }
}
```

Règles :
- Les enums sont traduits par concaténation : `{{ 'board.difficulty.' + mr.difficulty | translate }}`
- Les paramètres utilisent la syntaxe `{{name}}` et sont passés en second argument : `{{ 'board.ready.days' | translate: { days: 3 } }}`
- Les messages d'erreur des stores sont des clés (`'board.errors.load'`), traduits dans le template ou le snackbar

---

## 3. Utilisation

```ts
@Component({ imports: [TranslatePipe, MatButtonModule], ... })
```

```html
<button mat-stroked-button>{{ 'board.toolbar.refresh' | translate }}</button>
```

Dans le code (snackbar, aria-label dynamique) : `inject(TranslateService).translate('board.errors.sync')`.

---

## 4. Règles de contribution

- Ajouter les clés dans `fr.json` **avant** d'écrire le template
- Une clé manquante renvoie la clé elle-même et logue un avertissement en dev (détectable en test)
- Les tests chargent le vrai `fr.json` : un libellé attendu se vérifie par sa clé résolue, jamais par un texte dupliqué en dur
- Supprimer les clés orphelines lors d'un refacto (script `npm run i18n:check` à prévoir)
